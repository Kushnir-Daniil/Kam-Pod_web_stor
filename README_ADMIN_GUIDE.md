# Керівництво для адмінів: як наповнювати квести без коду

Цей документ для людей, які створюють **історії, комікси та ігри** на сайті Questy / Kam-Pod і викладають їх для гравців. Кодити не потрібно — достатньо адмін-панелі та підготовлених файлів (картинки, білд гри).

> **Статус зараз:** каркас конструктора вже є (`admin/quest-editor.html`), форми збереження ще допрацьовуються. Нижче описано **цільовий процес**, як ним користуватись після готовності конструктора, і що можна робити вже сьогодні.

---

## Хто такий адмін / казкар

1. Зареєструйтесь / увійдіть на сайті (`register/`).
2. **Адмін:** email зі списку в системі → вкладка **«Адмін»**.
3. **Казкар:** при реєстрації оберіть «Казкар» і введіть код з Firestore `inviteCodes` → вкладка **«Казкар»** (бібліотека + конструктор).
4. Новий квест казкаря зберігається зі статусом **«не опубліковано»** (`draft`). Публікація в каталог — лише після модерації адміном (наступний етап UI).

Гравці бачать опубліковані квести у вкладці **«Квести»**.

---

## З чого складається один квест

Кожен квест — це одна «пригода» з трьох частин (як на макетах):

| Частина | Що бачить гравець | Що готує адмін |
|---------|-------------------|----------------|
| **Історія** | Картинка + текст (розділи, «Далі / Попередня»), нагорода | Текст українською + ілюстрації сторінок |
| **Комікс** | Сцена з діалогами персонажів, керування сценами | Кадри + репліки (хто говорить і що) |
| **Гра** | Екран «ГОТОВІ ДО ПРИГОД?» → кнопка **ГРАТИ** | Готовий WebGL-білд гри + (опційно) локація на карті |

Гравець спочатку проходить історію та/або комікс; гра може бути **заблокована**, доки контент не завершено, і/або доки гравець не підійде до реальної локації (геозона).

## Підготовка матеріалів (без коду)

### 1. Обкладинка квесту

- Одна картинка для списку квестів (квадрат або горизонтальна ілюстрація).
- Формат: PNG або JPG.
- Зрозуміла назва файлу, наприклад `cover.png`.

### 2. Історія

На кожну сторінку історії підготуйте:

- **Зображення** (ілюстрація розділу)
- **Заголовок розділу** (наприклад: «Розділ 1. Загадковий запис»)
- **Основний текст**
- **Цитату** (за бажанням — виділений блок)

Кількість сторінок — будь-яка (на макеті часто 5).

### 3. Комікс

На кожну сцену:

- **Зображення** сцени
- **Репліки**: ім’я персонажа + текст  
  Приклад: `Драко` — «Давним-давно…»; `Оленятко` — «Книгу знань?…»

### 4. Гра

1. У Unity зробіть **Build → WebGL**.
2. Передайте технічній команді або викладіть у папку сайту:

```
builds/game-N/
  index.html
  Build/
  TemplateData/
```

3. Запам’ятайте ім’я папки: `game-1`, `game-2`…  
   У конструкторі в полі гри вказуєте саме це ім’я — **код писати не треба**.

Якщо гра має відкриватись лише біля місця в Кам’янці — підготуйте:

- назву місця (наприклад, «Папська вежа»)
- координати (можна з Google Maps: клік по точці → скопіювати lat/lng)
- радіус у метрах (наприклад, 70–80 м)

## Як створити квест у конструкторі (цільовий сценарій)

1. Увійдіть як адмін → **Адмін**.
2. Відкрийте **Квести / конструктор** або **+ Новий квест**.
3. Заповніть вкладки по черзі.

### Вкладка «Мета» (загальне)

- Назва квесту  
- Тип / жанр (Комікс, Казка, Пригода, Навчальна…)  
- Тривалість (наприклад, «15 хв»)  
- Короткий опис для картки в списку  
- Обкладинка  
- Нагороди: XP, монети, кристали  

Збережіть чернетку.

### Вкладка «Історія»

- Додайте сторінки кнопкою на кшталт **«+ Сторінка»**
- Для кожної: завантажте картинку, вставте заголовок, текст, цитату
- Порядок сторінок можна змінювати (вгору / вниз)
- Збережіть

### Вкладка «Комікс»

- Додайте сцени **«+ Сцена»**
- Для кожної: зображення + список реплік (персонаж + текст)
- Збережіть

### Вкладка «Гра»

- Оберіть білд зі списку або вкажіть папку (`game-1`…)
- Укажіть, після чого відкривати гру: після історії / коміксу / обох / одразу
- За потреби увімкніть геозону і вкажіть місце + радіус
- Збережіть

4. Опублікуйте квест (статус «Опубліковано»), щоб він з’явився у гравців у **Квести**.

5. Перевірте як гравець:

- **Квести** → картка → відкрити  
- вкладки Історія / Комікс / Гра  
- кнопка **ГРАТИ** (і геолокація на телефоні, якщо увімкнена)

## Куди класти файли на сайті (для команди / адміна з доступом до репозиторію)

Поки завантаження з браузера (Firebase Storage) може бути ще не підключене, файли можна додати так:

| Що | Куди |
|----|------|
| Обкладинки й кадри історії/коміксу | `content/quests/<slug-квесту>/` |
| WebGL-ігри | `builds/game-1/`, `builds/game-2/`, … |
| Іконки інтерфейсу сайту | `img/` (звичайним адмінам не чіпати) |

Після додавання файлів технічна команда робить оновлення сайту (або ви пушите в GitHub, якщо так домовлено).

У конструкторі в полях картинок вказуєте шлях або обираєте файл зі списку — **без редагування HTML/JS**.

## Чеклист перед публікацією

- [ ] Назва, опис і обкладинка заповнені  
- [ ] В історії є хоча б одна сторінка з текстом і картинкою  
- [ ] Комікс заповнений або свідомо пропущений (якщо квест лише з історією)  
- [ ] Гра прив’язана до існуючої папки в `builds/` і відкривається кнопка «ГРАТИ»  
- [ ] Якщо є геозона — координати й радіус перевірені (або тестовий режим на ПК)  
- [ ] Нагороди (XP / монети) виставлені коректно  
- [ ] Переглянуто з акаунта звичайного гравця

## Типові питання

**Чи можна змінити квест після публікації?**  
Так — відкрийте його в адмін-списку квестів → редагувати → зберегти.

**Що робити, якщо гра не відкривається?**  
Перевірте, що в `builds/game-N/` є `index.html`, і що в квесті вказана саме ця папка. На телефоні для геозони зазвичай потрібен HTTPS.

**Де зберігаються користувачі?**  
У Firebase (Authentication + Firestore). Паролі в базу квестів не пишуться.

**Де описана технічна структура папок?**  
У файлі [README_STRUCTURE.md](./README_STRUCTURE.md).

## Що попросити в розробників, якщо чогось немає

1. Форми збереження в конструкторі (історія / комікс / гра).  
2. Завантаження картинок у Firebase Storage з адмінки.  
3. Публікація квестів у Firestore (щоб бачили всі пристрої, не лише ваш браузер).  
4. Запуск Unity-гри в iframe з перевіркою геолокації.

Коли ці пункти готові — цей гайд можна виконувати повністю без участі програміста на кожен новий квест.
